# AI 研发流程审查

中文 | [English](WORKFLOW_AUDIT.en.md)

审查日期：2026-10-29。对象为 AGENTS/启动资料、AI 开发指南、构建/采集/比较/字体/CPU/发布工具及源码 CI。结论：**在固定 3.0.8 兼容范围、环境资源可用、外部操作已有授权的条件下，AI 有完整执行路径；不能承诺任意新功能在任意环境中无人介入、无遗漏地自动通过。**

## 1. 本轮发现与处理

| 问题 | 本轮处理 | 仍须区分的边界 |
| --- | --- | --- |
| 流程分散，缺少统一任务起点与完成标准 | 新增 AUTONOMOUS_WORKFLOW、机器 workflow.json、init 计划与验收标准 | AI 仍需理解需求并选择语义影响范围 |
| 文档更新只在结尾建议，代码可完成但资料缺失 | AGENTS 明确同批文档交付；文档主题映射；变更记录与 CI 检查 | 结构检查不能证明说明文字正确 |
| 英文、demo、图片、安装信息容易遗漏 | DOCUMENTATION 列出触发条件和双语/图片/版本要求；既有校验纳入统一 run | 图片和翻译语义需实际审阅 |
| 源码候选版本与已发布安装版本耦合 | 引入 sourceVersion、installation.version、acceptedWheels.version，候选可独立演进 | 公开文档切换版本仍须审阅与实际索引核对 |
| PyPI 说明仍为上传时旧 README，误导 AI | 新增只读 wheel 元数据质量检查；发布流程要求检查实际包描述 | 无法改写旧版本元数据；必须保留原验收 wheel |
| 源码改变后，旧检查可能被当作当前通过 | SHA 覆盖、refresh 失效旧记录；本地检查证据 SHA/源码/文档上下文 | 对复杂原生报告还须审阅真正比较对象和范围 |
| 缺少统一失败记录与恢复入口 | 每个命令保留日志/退出码，源检查有超时；新 run、previousChecks、nextStep | 中断后的不完整 run 不能当作成功，应新建重跑 |
| CI 只验证资料，无法约束代码/文档对应 | checkout 完整历史；按 PR base/push before 做变更覆盖检查 | hosted CI 没有本机 GPU/font 证据，不能重新证明其真实性 |
| 默认 GPU、CPU、字体、GUI 与发布易混为一类 | 按 area 和 kind 生成最小需求；保留全发行门槛 | area 选择是开发审阅，不是全 API 覆盖率证明 |
| 新扩展可能无意突破固定上游 | extension 需写明用户兼容决策；生产改动不能标成 tooling | JSON 文字不授予用户权限，也不允许算法替换 |

## 2. AI 可以自主执行的工作

| 环节 | 执行方式 | 可检查结果 |
| --- | --- | --- |
| 起点/需求/影响 | Git 状态、init、验收标准、areas 与文档主题 | 固定 base、未执行清单、已有用户修改 |
| 复现/实现 | 原 A/旧 wheel、独立断言、共享 core/绑定修改 | 修改前失败与修改后行为、来源映射 |
| 构建/安装 | 现有 Windows/manylinux 脚本、隔离环境 | 实际候选及 SHA、无 Node/工作区依赖 |
| 功能验证 | capture/compare、CPU matrix、生命周期、native/font 工具 | 每模式/平台/后端精确结果与真实资源 |
| 文档/图片 | 双语更新、实际 demo、manifest、包描述检查 | 用户可执行说明、可读输出与固定来源 |
| 最终核对 | run、attach、check --verify-evidence、diff/视觉审阅 | 原始报告、源码/文档 SHA、完整交接 |
| 外部交付 | 当前授权下的 GitHub/索引 CLI，下载独立回验 | 实际 commit/run/release/index 状态 |

工具把重复检查和记录处理自动化，AI 负责语义推理、编码、解释失败并调用对应 CLI；这不是无需 AI 决策的一键任意功能生成器。

## 3. 无法由流程文本消除的条件

必须有目标 GPU/驱动、字体及使用权限、GUI 桌面、真正无 loader 的部署环境，以及需要的账号访问。软件 Vulkan 与 CPU Raster 不等同；驱动屏蔽与无动态库不等同。缺少条件就保留相应未验收项，同时推进其他独立工作。

默认行为、兼容基线、平台范围或绘图算法若需改变，必须有本次用户决策。已有授权可持续执行，不应反复确认；未授权的外部发布不能靠记录文件自动获得授权。

新功能的全面性由需求契约、回归、原 A 精确差分、真实资源、生命周期及发行矩阵共同支持。测试和审阅仍可能漏掉未想到的情况；不能将 `CHANGE_COVERAGE_CHECKED` 或“没有失败”扩大为无条件正确。

## 4. 本轮验证与验收范围

新增流程工具的单测使用临时 Git 仓库，覆盖缺记录、未完成计划、漏英文、无理由跳过文档、源码/文档/证据过期、生产改动误标、路径越界、只读来源变更、Unicode 路径、旧证据失效与失败日志保存。版本测试覆盖“a19 候选、a18 安装”并存；包描述测试覆盖过时发布措辞、仅本地安装、版本和链接错误。

本批是研发流程/文档/校验工具修改。按 tooling 范围执行源码、工具和双语文档检查，不重编生产库、不把历史 GPU/CPU 渲染结果冒充本批新功能验收。任务记录见 [本批记录](../../changes/20261029-ai-development-workflow.json)，原始证据在 `test-runs/20261029-ai-workflow-1/`。

## 5. 后续使用要求

2026-11-02 发行审查发现：没有专用成功状态白名单的原生检查，曾接受 `FAILED` 报告。现统一拒绝失败、错误、未执行、跳过、超时、阻塞等负面状态及非字符串状态，并增加回归断言。状态检查仍不代替对原始结果和实际比较对象的审阅。

以 [AUTONOMOUS_WORKFLOW](AUTONOMOUS_WORKFLOW.md) 执行新任务，按 [DOCUMENTATION](DOCUMENTATION.md) 同批交付文档。每轮保留实际缺项和可恢复步骤；任务开始前配置各平台路径/资源，并在新功能影响范围内验证。要获得更高程度的无人值守执行，还需持续可用的 GPU/GUI/无库运行环境与受控账号环境，而不只是更多流程文字。
